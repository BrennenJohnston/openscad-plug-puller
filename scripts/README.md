# scripts/

Utility scripts used to build and validate the Plug Puller model's committed artifacts. All paths are relative to the repo root; run them from there, e.g. `python scripts/build_flattened.py`.

## Contents

| Script | Purpose |
|--------|---------|
| `build_flattened.py` | Deterministically inline each model's include tree into its single-file artifact for web customizers (the OpenSCAD Assistive Forge's example branch, MakerWorld PMM, openscad-playground `?src=` loading): `dist/Plug_Puller_One_Sided_SingleFile.scad` from `src/Plug_Puller_Parametric.scad` (inlines `src/fit_sizes.scad`, `src/fit_measured.scad` and `src/presets.scad`) and `dist/Plug_Puller_Two_Sided_SingleFile.scad` from `src/Plug_Puller_Two_Sided.scad` (inlines `src/fit_sizes.scad`); `--check` verifies both are fresh (CI does this on every run). |
| `regenerate_fixtures.py` | Re-render every golden STL under `tests/fixtures/<name>/reference.stl` from its `params.json`, and refresh the matching `metadata.json` with OpenSCAD version + trimesh measurements. Run after any intentional SCAD change so the mesh-comparison tests in `tests/test_render_modes.py` keep validating actual deltas, not stale references. Writes binary STLs, and leaves a fixture alone, `metadata.json` included, when its shape did not change; `--force` rewrites every one. |
| `build_release_stls.py` | Render the committed ready-to-print library under `stl/`: 15 plug tools in `stl/Plug-Puller/` (9 one-sided pullers for the USB-C tip, lamp and wide appliance plug presets × 3 hand sizes, and 6 two-sided pullers for the standard and heavy-duty cord presets × 3 hand sizes, both plates in each file) + 18 measuring-stencil cards (Visual/Tactile full sets and individual cards, in `stl/Measuring-Stencil/`). Each output is a binary STL, without the zero-area triangles that binary's 32-bit coordinates leave where OpenSCAD's shortest edges collapse, and is watertight-checked; a file whose shape did not change is left alone, and `--force` rewrites every file. Run after any intentional model change and commit the refreshed `stl/`; `tests/test_shipped_stls.py` reuses this script's job catalog to guard the shipped files. Use `--only plug-puller` / `--only stencil` to rebuild one group. |
| `generate_outline_sheets.py` | Generate the try-before-you-print outline sheets (`docs/guides/outline-sheets/`, 15 SVGs): render each quick-select combination (the USB-C tip, lamp and wide appliance plug presets × 3 sizes for the one-sided puller, plus one two-sided puller plate for the standard and heavy-duty cord presets × 3 sizes) via the OpenSCAD CLI, extract the true 1:1 silhouette / through-holes / pocket opening with trimesh + shapely, compute the labeled dimensions from `tests/fit_formulas.py`, and compose A4/Letter SVG sheets with CAD dimension lines and a calibration square. Asserts dimension parity between the mesh, the formulas, and the sheet before writing. Re-run after any geometry or preset change. |
| `build_outline_sheets_pdf.py` | Bundle the 15 outline-sheet SVGs into the printable `docs/Plug_Puller_Outline_Sheets.pdf` (cover/index page + one sheet per page) via headless Edge/Chrome — the same Skia print pipeline as the other PDF guides. The `@page` size equals the SVG page (210 × 279 mm) so the sheets keep their exact 1:1 scale; the script verifies the page count and every page's MediaBox after printing, then the document title and a bookmark on every page (hidden headings name each plug and each hand size; Chromium places a bookmark only where its heading is painted). Run after `generate_outline_sheets.py`. |
| `generate_stencil_sheet.py` | Emit `docs/guides/stencil-sheet.svg`, the 1:1 paper alternative to the 3D-printable `Measuring_Stencil.scad`'s ruler and finger cards: one 210 × 279 mm page with the 50 mm calibration square, a 100 mm ruler, and the 18 finger circles. The paper stand-in for the P plug cards is the plug size finder below. |
| `generate_plug_finder.py` | Emit `docs/guides/plug-size-finder.svg`, the one-page plug size finder: every plug preset of both tools at 1:1, lying on its wide side with its prongs (or USB-C metal tip) and its cord, grouped by tool (2 prongs or a USB-C tip: the one-sided puller; 3 prongs: the two-sided puller) and labelled with the preset to pick, plus a 50 mm calibration square and the five steps. The numbers come from `generate_outline_sheets.PLUG_PRESETS`; `finder_text()` is the page's text equivalent, which the guides print. `tests/test_plug_finder.py` checks every outline against its preset. Re-run after any preset change. |
| `generate_measuring_form.py` | Draw the two measuring form sheets, `docs/guides/one-sided/measuring-form.svg` and `docs/guides/two-sided/measuring-form.svg` (210 × 279 mm): a Start here box (the prong count that picks the tool, and a blank for the closest outline on the plug size finder), then one row per Step dial in Customizer order from the parameter mappings (the name, the plain title, the default and a blank, or tick boxes for a dropdown), a schematic plug drawn from the tool's defaults at 1.5:1 with a knuckle bar and a strap bar at 1:1, and a straight numbered leader from every measured row to a red dimension line on the feature its catalog `measure.anchor` names. `build_sheet()` also returns the form's text (the rows as a table, then what the sheet shows), which `build_dial_reference.py` places in each tool's quick start and full guide. The script fails if two leaders cross or a leader runs through a drawing. |
| `generate_dial_diagrams.py` | Draw one diagram per Customizer dial under `docs/dials/` from `dial_catalog.json` (reads the two parameter mappings for the defaults): each row is rendered twice via the OpenSCAD CLI (the defaults plus the row's context, then the dial at its `after` value), the top view is extracted with the outline-sheet helpers (shadow silhouette, through-holes and pocket recess for the one-sided puller; the contact-face section for a two-sided plate), and the symmetric difference becomes the red dashed trace over the black default outline and the teal plug. Writes `docs/dials/one-sided/<name>.svg`, `docs/dials/two-sided/<name>.svg` (1 unit = 1 mm, with `<title>` / `<desc>` text equivalents; "no shape" rows get a 120 × 40 mm card) and `docs/dials/dial_diagrams_index.json` (values, region count, changed area, warning tags and the named features the trace touches, per dial), then `docs/dials/README.md` (every diagram inline with its sentence as alt text; `--readme` rewrites it alone from the index). Renders are cached under `tmp_renders/dial_diagrams/` (keyed by the parameter set and the SCAD sources; `--force` re-renders). `--file`, `--only NAME` and `--views {top,none,section,all}` limit a run. A full forced run of all 119 rows is 214 renders, about 6 minutes on the reference PC (measured 2026-09-26: the 89 top rows 4 min 43 s with 148 s inside OpenSCAD, the 18 section rows 39 s); a cached run of every row about 3 minutes. |
| `build_dial_reference.py` | Build one tool's two guide documents (`--tool one-sided` or `--tool two-sided`; `--document quick-start` or `full-guide`, default both) from `dial_catalog.json` (its `measure` rows too), both parameter mappings, `docs/dials/dial_diagrams_index.json`, `docs/dials/storyboards_index.json`, the measuring form's text, the plug size finder's text and the hand-written sources under `docs/guides/source/` (one topic each, loaded and converted by `guide_text.py`): the pages `docs/guides/<tool>/quick-start.md` and `full-guide.md`, and the PDFs `docs/Plug_Puller_<Tool>_Quick_Start.pdf` and `..._Full_Guide.pdf` on US Letter pages (a cover, a contents page with page numbers, the sections as cards and prose that flow down the pages with no picture above 1:1, and the 210 × 279 mm plug size finder, measuring form and paper stencil sheet centered at 1:1 on the last pages; the document's name at the top and "Page N of M" at the bottom of every flowing page). Every dial is a card headed by its plain title, then the name the Customizer shows, the sentence of what it does, the picture with its alt text and its long description less the clause that repeats that sentence (or a "No picture." line for a dial that changes no shape), its numbers in plain words, the parts it moves and the red warnings it can raise (a hand-kept table read off `docs/guides/source/tags-*.md`). The PDF is printed with headless Edge through `build_outline_sheets_pdf.print_to_pdf` until the contents' page numbers settle, then verified (every page US Letter, one outline entry per heading with every dial's title among them, a link per contents entry, the contents' numbers equal to the pages their links land on, the page count's bounds). `--markdown-only` needs no browser. Run both tools after `generate_dial_diagrams.py`, `generate_measuring_form.py`, `generate_stencil_sheet.py` and `generate_plug_finder.py`. |
| `guide_text.py` | The hand-written text of the guides: loads one source file under `docs/guides/source/` for a tool (filling `{tool}`-style placeholders; `PLACEHOLDERS` lists them) and turns the Markdown subset the sources use into HTML for the print (headings, paragraphs, lists with an image inside an item, pipe tables, fenced code, block quotes, images, links, bold, inline code). Standard library only; tested by `tests/test_guide_text.py`. |
| `render_doc_images.py` | Render the three preview PNGs the guides embed, from today's model files with the canonical OpenSCAD binary: `docs/images/one-sided-medium-render.png` (the one-sided puller at its defaults), `docs/images/two-sided-plate-render.png` (both plates of the two-sided puller at its defaults) and `docs/images/one-sided-warning-tag-preview.png` (a 27 mm thick plug, so the W-20 warning's red text lies beside the part; a plain PNG export is a preview, so the see-through plug and the tags show). Standard library only; `--only NAME` renders one. Re-run after a model change that moves what these pictures show. |
| `build_open_at_pdf.py` | Print the Open AT document set (`Documentation/*.md`, the nine pages its `DOCUMENTS` table lists) to tagged US Letter PDFs with headless Edge or Chrome: a cover, a contents page with page numbers, figures with their alt text and captions, the Check, By touch and Careful paragraphs as callouts. It reprints until the contents settle and shrinks a page's pictures where one fell off its heading's page, then verifies the PDF and writes a record per document under `scripts/pdf_records/` (the SHA-256 of the PDF and of every input), which `tests/test_open_at_pdf.py` compares in the quick lane. `--document all` (default) or one name. Ported from the Accessible Open AT Documentation Template. |
| `pdf_structure_report.py` | Print a tagged PDF's structure tree as text, the order a screen reader follows, with each figure's alt text and each table cell's scope. Needs pypdf. |
| `photo_import.py` | Cut every guide photograph of `Documentation/images.json` from its full-size master (`--masters`, or `PLUG_PULLER_MASTERS`) by its crop box into `Photos/<group>/<name>`: 3:2, 1600 px on the long edge, JPEG quality 85, sRGB, no EXIF; writes the file's SHA-256 back into the record. Needs Pillow. |
| `makerworld_photos.py` | Make the MakerWorld listing's pictures in `MakerWorld_Photos/`: the two covers (4:3 desktop, 3:4 app) and the real photos cut from their masters (`--masters`, `--july`), and four renders drawn by OpenSCAD from shipped STLs. Needs Pillow and OpenSCAD. |
| `forge_screenshots.py` | Take the Browser Customizer Guide's five screenshots from the live OpenSCAD Assistive Forge with headless Edge (Playwright), handing the browser this repository's single file, presets and manifest in place of the Forge branch's copies, and mark each control with a numbered red box, into `Photos/screens/`. |
| `makerworld_listing_docx.py` | Write `Documentation/Plug_Puller_MakerWorld_Listing.docx` from the listing's Markdown, each field under its heading and each picture where it goes with its alt text and file under it. Needs python-docx and Pillow. |
| `listing_description_markdown.py` | Write `Documentation/Plug_Puller_Listing_Description.md`, the listing's description as plain Markdown with no pictures, for Printables and Thingiverse; `--check` exits 1 when it is stale (the quick lane runs it). Standard library only. |
| `makerworld_bundle.py` | Write `build/makerworld/Plug_Puller_Guides.zip`: the seven step guides, the Device Summary and the Design Rationale as PDFs, and each tool's quick start and full guide, for MakerWorld's model-file slot, which refuses PDFs. Standard library only. |
| `shot_list.py` | Write `Documentation/Shot_List.md` from the shot requests (`<!-- shot: ... -->`) in the Open AT pages; `--check` exits 1 when it is stale (the quick lane runs it). Standard library only. |
| `check_docs.py` | The documentation gate: check `README.md`, `stl/README.md`, every `docs/**/*.md` and `Documentation/*.md` against the writing standard's mechanical rules (one H1, no skipped heading level, alt text on every image, no "click here" or "check the console", table cells of at most 22 words, no banned, hedging or retired words, every relative link resolving, no compliance claim). Prints `<file>:<line>: <rule>: <detail>` per finding and exits 1 on any; prints nothing when clean. `tests/test_docs_gate.py` runs it in the quick lane. Standard library only. |
| `scad-check.ps1` | The headless check to run after any `.scad` change, in Windows PowerShell: `powershell -ExecutionPolicy Bypass -File scripts\scad-check.ps1 -File src\Plug_Puller_Two_Sided.scad` renders the file (default `src\Plug_Puller_Parametric.scad`) to `build\check.stl` with OpenSCAD's hard warnings and parameter range checks on, using the 2026.01.03 nightly (or the path in `OPENSCAD_EXE`). `-Defines 'size=Measure my hand'` sets a dial, with or without quotes around a text value; a text value that is not one of the dial's dropdown choices counts as a warning. It prints OpenSCAD's full output, then `CHECK PASSED`, or `CHECK FAILED` when any line has `WARNING:` or `ERROR:` or no STL was written. |

## Prerequisites

- Python 3.11+ with the dev dependencies installed: `pip install -r requirements-dev.txt`
- OpenSCAD 2026.01.03+ nightly (Manifold backend) on `PATH`, or set `OPENSCAD_PATH` — needed by `regenerate_fixtures.py` and `generate_outline_sheets.py`.
- Microsoft Edge or Chrome — needed by `build_outline_sheets_pdf.py` and `build_dial_reference.py` for headless SVG-to-PDF printing.
